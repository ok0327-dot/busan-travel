# busan-travel 정보 흐름 감사 (Information Flow Audit)

> 작성일 / Date: 2026-04-25
> 범위 / Scope: 수집(ingest) → 검증(filter) → 저장(store) → 가공(transform) → 표현(present) → 만료(expire) 6개 구간 전수 점검
> 목적 / Goal: "가만히 있어도 노이즈 없는 양질의 정보가 알아서 쌓이고 적시에 표현되는" 구조의 결함 지점 식별 + 정비 계획 도출

---

## 0. TL;DR

- **소스 어댑터 14개 중 5개만 v3.9 컨트랙트(HTTPSession+report) 마이그레이션**, 2개(naver_blogs, naver_local)는 legacy raw 호출.
- **`filter_events()` 가 선언만 되고 ingestion 어디서도 호출 안 됨** — 노이즈 필터가 export 시점 단일 게이트로만 동작 (이중 정의 / 단일 적용).
- **`weather-only` cron(3시간마다)이 `export_json.py` 를 무가드 호출** → R2 의 stale events.db 를 다운받아 places.json 을 덮어쓸 수 있는 silent overwrite 경로 확인됨.
- **`lodging` 카테고리는 코드/DB 양쪽에서 누락** — 메모리(`busan_travel_project.md`)의 "숙박 362건" 진술과 진실원 불일치.
- **AI Pick / 사이드카 분류 / 사용자 즐겨찾기 등 진실원이 5곳에 분산** (DB / static JSON / Python dict / LocalStorage / R2). 단일 정답이 어디인지 흐림.

## 5. 잘 된 점 (Keep)

- ✅ **HTTPSession+report 컨트랙트** — v3.9 에서 5개 어댑터 표준화 (rate limit/retry/timeout 일관).
- ✅ **gov-api-kr vendor + DATA_GO_KR_KEY 중앙화** — 정부 API 키 단일 진입점.
- ✅ **Deterministic export** — `ORDER BY` 정렬 안정, 두 번 돌려도 같은 결과.
- ✅ **trust_tier + raw_json 보존** — 신뢰도 계층 + 재파싱 가능.
- ✅ **VisitBusanClient 캐시 + rate limit** — 개발/테스트 빠르고 사이트 부담 적음.
- ✅ **부산 bbox 좌표 검증** — TourAPI 등 외부 좌표 오염 자동 차단.
- ✅ **manifest.adapters freshness tracking** — 소스별 last_seen 노출 가능.
- ✅ **Worker 캐시 전략 명확** — `/img/*` immutable 1y, `/img-proxy/*` edge 31536000s.
- ✅ **dedup specificity promotion (v3.9 보험)** — 미래 silent overwrite 차단 코드 들어감.
- ✅ **cron 실패 → GitHub Issue 자동 생성** (P1 완료, 단 continue-on-error 흡수 한계 있음).
- ✅ **R2 mirror + GitHub Actions cache 이중 백업** — 빈 fresh start 위험 완화.

## 7. 다음 결정 (User Decision)

**(a) 보고서 자체에 대한 피드백**: 빠진 구간/요청 세분화 있으면 알려달라.
